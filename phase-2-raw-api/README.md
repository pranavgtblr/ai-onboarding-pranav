# Phase 2: Raw API — Building Without Frameworks

Welcome to **Phase 2** of the AI Engineering Onboarding!

In this phase, we interact directly with the LLM REST API using Python's `httpx` and the standard library. No LangChain, no LlamaIndex, no hidden abstractions. If you learn agent frameworks before writing raw HTTP requests, every network glitch, token overflow, or formatting error looks like a mystery. Once you build the raw protocol by hand, frameworks become completely transparent.

---

## Task 2.1: Single Raw HTTP Completion Call

### Objective
Make a single completion call to the LLM API using raw `httpx`. Inspect and print:
1. **Generated Content** (the actual text response)
2. **Stop / Finish Reason** (e.g. `STOP`, `MAX_TOKENS`, `SAFETY`)
3. **Input Tokens** (prompt token count)
4. **Output Tokens** (candidate/generation token count)
5. **Total Tokens**

---

### What Happens Under the Hood? (Frontend / JS Analogy)

In frontend development, you make raw HTTP calls all the time:
```ts
// TypeScript / Fetch equivalent
const response = await fetch("https://api.provider.com/v1/generate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": process.env.API_KEY,
  },
  body: JSON.stringify({
    prompt: "Explain recursion in one sentence."
  })
});
const data = await response.json();
```

In Python with `httpx`, we do the exact same thing:
1. **Endpoint**: `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
2. **Headers**: `{"Content-Type": "application/json", "x-goog-api-key": "<API_KEY>"}`
3. **Payload**:
   ```json
   {
     "contents": [
       {
         "parts": [
           {"text": "Your prompt here"}
         ]
       }
     ]
   }
   ```
4. **Response Structure**:
   ```json
   {
     "candidates": [
       {
         "content": {
           "parts": [{"text": "Recursion is..."}],
           "role": "model"
         },
         "finishReason": "STOP"
       }
     ],
     "usageMetadata": {
       "promptTokenCount": 8,
       "candidatesTokenCount": 29,
       "totalTokenCount": 37
     }
   }
   ```

---

### Key Concepts

#### 1. Stop / Finish Reason
Why does the model stop generating?
- `STOP`: The model naturally reached an End-Of-Sequence (`<EOS>`) token or finished its thought.
- `MAX_TOKENS`: The generation hit the output token ceiling (`maxOutputTokens`) and was truncated midway.
- `SAFETY`: The model's safety filters triggered and cut off the generation.
- `RECITATION`: The model was reciting copyrighted/memorized material and halted.

#### 2. Token Accounting
- **Input Tokens (`promptTokenCount`)**: Number of tokens in your request. In multi-turn chat, this grows every single turn because previous messages are resent.
- **Output Tokens (`candidatesTokenCount`)**: Number of tokens generated by the model. Output tokens are typically 3x to 5x more expensive than input tokens.
- **Total Tokens**: Sum of input and output. Essential for cost tracking, budgeting, and rate-limit tracking.
